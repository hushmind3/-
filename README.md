# 온라인 강화학습 기반 자율 포트폴리오 운용 에이전트

저장소 이름은 **Continual Trading Agent**입니다.

Transformer + Actor-Critic + Continual/Online RL + Portfolio Allocation 구조로, 시장을 관찰하고 현금 포함 자금 배분·진입·유지·청산을 결정하며 비용을 뺀 순자산 결과로 정책을 계속 학습합니다.

## 프로젝트 목표

이 프로젝트는 특정 trader나 고정 전략을 영구 모방하는 모델이 아닙니다. 모델은 시장, 종목, 시간축, 포트폴리오 상태를 바탕으로 종목 선택, BUY/HOLD/SELL, 자금 배분, 포지션 유지·증감·교체·청산을 경험으로 학습합니다.

Teacher 모델, 공개 모델, 과거 trader 기록은 초기 금융 문법을 익히는 교육 재료입니다. 최종 목표는 이 자료를 그대로 복사하는 것이 아니라 시장 경험과 보상을 통해 모델 자신의 정책을 발전시키는 것입니다.

수수료, 거래세, 슬리피지, 스프레드, 현금, 보유량, 평단, 실현·평가 손익, 유동성, 자본 규모와 체결 규칙은 환경이 계산합니다. 구체적인 매매전략과 자금 배분은 모델이 경험으로 발견합니다.

## 학습과 승급

### 운영 상태를 읽는 방법

- 화면의 시세 지연은 최신 수신 봉과 모델이 처리 완료한 봉의 시간 차이입니다. 모델 오류, GPU 대기, 오래된 관찰 처리 대기를 구분해서 표시합니다. 지연 중인 계좌 금액은 마지막 처리 시각의 값입니다.
- GPU 작업은 Champion·Candidate 실시간 판단을 먼저 처리하고, 가중치 반영·승급시험·replay 학습 순으로 처리합니다. 같은 우선순위에서는 요청 순서를 지킵니다. 학습은 시장 입력 한 묶음의 forward/backward와 optimizer 실행을 각각 나눠 GPU를 반환합니다. batch의 누적 gradient와 optimizer 횟수는 유지합니다. 미처리 관찰을 삭제하거나 시장 시점을 건너뛰지 않습니다.
- 학습은 실제 GPU 추론이 실행 중이거나 요청된 경우에 양보합니다. 미처리 관찰 건수·cursor 지연만으로 학습을 막지 않습니다. 판단 작업이 CPU·DB 처리 중이면 GPU에서 replay 학습을 진행할 수 있습니다. 학습 대기는 GPU 추론에 자원을 양보한 상태이며 미학습 경험은 보존합니다.
- 한국시간 20시부터 미국 본장 시작(뉴욕 09:30) 전까지는 replay 학습을 GPU에서 먼저 처리합니다. 이 시간에는 판단·승급전이 학습을 막지 않습니다. 시세와 미처리 관찰은 보존하고 남는 시간에 처리합니다. 미국 서머타임에 따라 판단 우선 복귀는 한국시간 22:30 또는 23:30이며 화면에 실제 우선순위를 표시합니다.
- 종목별 결과는 같은 시장 입력을 공유하며, 한 관찰에서 성숙한 경험과 pending 제거를 하나의 SQLite transaction으로 기록합니다. 두 모델의 checkpoint 저장 확인이 끝난 경험만 삭제합니다.
- 학습 화면은 운영 상태, 두 모델 계좌, 오늘 경험 생성·학습 완료·미학습, 승급시험 순서입니다. 비용 상세, 계산 시간, 모델 설정은 상세 패널에서 확인합니다. GPU 대기·forward 시간과 계좌 처리 전체 시간을 구분합니다.
- 목표 자산 대비 달성률은 현재 순자산 / 목표 순자산입니다. 10배 목표에서는 시작 시 10%이며, 학습량이나 지능 성장률을 뜻하지 않습니다. 원금 대비 손익과 실제 학습 완료 건수를 별도로 표시합니다.
- 입력 배열이 호환되지 않는 과거 경험은 보류 사유와 건수를 표시합니다. 보류 경험은 정상 경험의 학습이나 삭제를 막지 않습니다. 종목 대응을 확인할 수 없는 입력을 임의로 잘라 학습하지 않습니다.

### GitHub의 큰 replay 복구

미학습 replay가 GitHub 단일 파일 한도를 넘으면 일관된 SQLite 보존본을 각각 100 MiB 미만인 독립 gzip 조각과 `.restore.json`으로 Git에 저장합니다. 운영 DB를 나누거나 중복 운영하지 않습니다. 새로 내려받은 프로젝트에서 원본 DB가 없을 때만 동일 경로에 복원하며, 크기·SHA256·SQLite 무결성을 확인합니다. 기존 운영 DB가 있으면 덮어쓰지 않습니다. `.pt` 가중치는 별도로 준비합니다.

### 두 모델이 함께 배우는 장기 목표

- Champion과 Candidate를 목표형·보상형으로 분리하지 않습니다. 둘 다 실제 순손익 보상과 공통 10배 임무를 배우며, 양쪽의 경험을 같은 SQLite replay에서 각각 한 번 학습합니다.
- KRW와 USD는 별도 시드·별도 계좌입니다. 각 통화에서 비용 차감 순자산이 자기 시작 자산의 10배에 한 번 도달하면 해당 통화의 WIN을 기록합니다. 양쪽 통화의 목표를 달성하면 그 계좌의 장기 임무가 WIN입니다. 현재 목표는 KRW 1억 원과 USD 10만 달러입니다. 기간 제한은 없습니다.
- WIN 보상은 통화별 100점으로 시작합니다(`goal_win_bonus_points`). 이는 실제 돈이나 수익률이 아니라 학습용 성공 점수입니다. 같은 계좌 episode에서 재시작·재관측해도 중복 지급하지 않습니다. 겹치는 과거 행동의 결과 연결에 같은 사건이 사용될 수 있지만 WIN 사건 자체는 한 번만 기록됩니다.
- 판단 시 현재 통화별 자산 배율, 목표 배율, 남은 거리, 임무 진행 상태를 6개 숫자로 전달합니다. 작은 목표 보조층 30개 파라미터는 기존 체크포인트 로드 시 0으로 시작해 기존 출력을 보존하며, 정상 학습 때 함께 갱신됩니다. 과거 경험에 현재 목표 입력을 덧씌우지 않고, 새 경험과 이후 상태에 당시 목표 입력을 저장합니다.
- 행동 학습에는 종목의 보유·매수 목표 비중에 따른 성공 기여 점수가 연결되고, 계좌 가치 학습에는 실제 순손익과 계좌 성공 점수가 함께 연결됩니다. 공동 WIN으로 끝난 이전 경험에는 이후 예상 가치를 더하지 않습니다. 현금·보유량·손익은 WIN 기록으로 바뀌지 않습니다.
- 장기 운용 계좌는 매일 초기화하지 않습니다. 오전 7시 KST에 고정 시험본의 동일 조건 승급전을 판정하고, 다음 시험 계좌만 동일 시드로 새로 시작합니다. 사용자가 직접 누르는 계좌 초기화는 새 episode이며 이전 자산을 보상으로 만들지 않습니다.
- 승급 판정에는 목표 성공 점수를 넣지 않습니다. 기존의 동일 미래 입력·동일 출발자금·동일 비용·탐험 OFF 조건에서 비용 차감 계좌 성과로 비교합니다. 현재 승급 조건인 Candidate의 양수 성과와 Champion 초과 성과는 유지합니다.
- 화면에는 각 모델의 실제 자산 배율·목표 금액·진행률·WIN 상태, 공유 학습 방식, 장기 계좌 유지 및 승부 점수 기준을 표시합니다. 목표 진행률을 추가했다고 수익성 개선이나 10배 달성이 입증된 것은 아닙니다.

### 보상 점수와 이후 결과 연결

- KRW와 USD 가상계좌 각각에서 비용 차감 순자산 수익률 `+1% = +1점`, `−1% = −1점`입니다. 점수는 현금과 보유분 평가액을 포함하며, 이미 계좌에 반영된 비용을 다시 차감하지 않습니다.
- 실제 관측 시각마다 직전 점수와의 차이를 같은 replay SQLite에 한 번 기록합니다. 같은 시각 재처리·재시작은 추가 보상이 아니며, 계좌 초기화는 새 episode로 구분합니다.
- 새 행동 경험은 기본 3,600초 동안의 종목별 순손익 기여도 및 계좌 순자산 변화를 누적한 뒤, 다음 상태의 가치 예측을 더하는 n-step Actor-Critic 목표로 학습합니다. 할인계수는 1.0입니다. 다음 상태 계산은 gradient 없이 실행하며 같은 입력은 회차 안에서 공유합니다.
- 현재 1분 데이터에서는 약 60개 관측이지만, 미래에 15초·30초 입력을 연결하더라도 보상 연결 시간은 1시간으로 유지됩니다. 이는 모델 입력창이나 강제 보유시간이 아닙니다. 이후 예상 가치가 이어지므로 1시간 이후의 결과도 가치 학습을 통해 연결됩니다. 계좌 초기화 시에는 이전 계좌의 최종 결과로 종료하고 새 시드 자금을 보상에 넣지 않습니다.
- 겹치는 1·5·30·60분 수익을 여러 보너스로 더하지 않습니다. 학습용 누적 목표와 화면의 실제 누적 점수는 별개입니다. 화면의 계좌 점수는 다음 상태의 예측값을 포함하지 않습니다.
- 기존 미학습 경험과 미완성 경험은 그대로 남깁니다. 기존 경험은 기존 짧은 목표로 소진하며, 새 방식과 기존 방식의 학습량을 회차별로 따로 기록합니다. 결과 연결 대기 경험은 재시작해도 남고, 두 모델의 checkpoint 저장 완료가 확인된 경험만 삭제합니다.
- 희귀함 자체에는 수익 보너스를 주지 않습니다. 이번 변경은 희귀 장면의 복습 횟수를 임의로 늘리거나 주말 전체 본체 학습을 추가하지 않습니다. 학습 범위·승급 원칙·실주문 OFF는 현재 설정을 유지합니다.
- 설정은 `configs/online_learning.json`의 `reward_credit_seconds`와 `reward_credit_discount`에서 확인합니다. `reward_credit_observations`는 기존 관측수 방식의 미완성 경험을 위한 호환 설정입니다. 운영 화면의 학습 영역에는 두 계좌의 점수와 실제 적용 중인 결과 연결 방식이 표시됩니다.

### 두 모델의 별도 판단과 계산 최적화

학습은 시세 관찰·가상매매와 별도 스레드에서 진행합니다. SQLite의 WAL/SHM 보조 파일은 정상 처리 중에도 사라질 수 있으므로 용량 조회에서 없는 파일을 0으로 취급합니다. 통계 조회 오류는 원인을 기록하고 재시도하며 학습 루프를 종료하지 않습니다. API의 학습 활성 여부는 실제 학습 스레드 생존 상태도 확인합니다. 경험 누적과 가중치 갱신 횟수는 학습 진행량이며, 수익성 개선은 동일 조건의 미학습 승급전으로 별도 확인합니다. 종목 수 제한·강제 관망·강제 매매 전략을 이번 복구에서 추가하지 않습니다.

Champion·Candidate 비교표는 양쪽의 역할, 학습 상태, 자체 가중치 변화량(L1), 누적 판단, 최근 학습 경험·optimizer 횟수·계산/전체 시간, 회차 중 프로세스 VRAM을 같은 항목으로 표시합니다. 둘 다 운영 추론·독립 가상매매·공통 경험 학습을 수행하며, 승급전에서만 Champion 고정본은 기준, Candidate 고정본은 도전자 역할입니다. 진행 중 점수는 현재 시험 계좌로 계산하고 과거 완료 점수를 재사용하지 않습니다. 현재 관측 길이와 양쪽 고정 버전을 확인할 수 없는 이전 운영 점수는 상세 역사 기록으로만 취급합니다.

실제 시장 입력이 128종목보다 적으면 텐서 정렬용 빈 패딩 칸이 포함될 수 있습니다. 패딩은 거래 종목이 아니므로 Candidate의 경험 생성은 실제 관측 마스크를 먼저 확인한 뒤 종목 정보를 조회합니다. 이 처리 순서로 빈 칸 조회의 `KeyError`가 필수 관찰 대기열을 막는 문제를 수정했습니다. 실제 종목·관측·미학습 경험을 삭제하는 처리는 추가하지 않습니다.

Champion과 Candidate는 같은 필수 시장 관찰을 각자 추론하고 독립 가상계좌로 매매합니다. 각자의 행동·비용 차감 손익을 한 replay에 합쳐 두 모델이 각각 학습합니다. 판단 횟수나 관찰 종목을 줄이는 최적화는 적용하지 않습니다.

이미 학습된 가중치를 복사할 때 0.5B 모델의 임의 초기값을 먼저 생성하는 작업을 없앴습니다. Candidate의 완료 가중치를 운영 추론에 적용할 때도 기존 모델 저장공간을 재사용하며, 새 가중치 적용 후 장기 기억 캐시를 무효화합니다. 운영 관찰과 승급전은 동일 시각의 시장 입력 준비 결과를 공유합니다. GPU 메모리를 확보하기 위한 Candidate의 RAM↔GPU 이동은 유지합니다.

운영실의 두 계좌 제목은 모두 **실시간 판단·가상매매**입니다. 추론·학습 시간 상세에는 Candidate의 잠금 대기, 모델 이동, 입력·forward, 합계와 두 모델의 최근 학습 계산/전체 시간을 구분합니다. 이 경과 시간은 다른 GPU 작업의 영향을 받을 수 있어 모델별 독점 GPU 사용률이 아닙니다. HTML 변경은 다음 요청에 반영되어 화면 수정만으로 서버 재시작이 필요하지 않습니다.

### 현재 운영 기준: 하루 승급전

운영 설정은 [configs/online_learning.json](configs/online_learning.json) 한 곳에 있습니다. 검증 시작 순간의 Champion과 Candidate를 RAM에 고정해 같은 미래 시장 입력·같은 시드·같은 체결 및 비용으로 하루 승급전을 치릅니다. **최소 390개의 서로 다른 시장 분 관측, 유효한 동일 조건, Candidate 비용 차감 수익률 합 > 0, Candidate > Champion**을 모두 만족해야 합니다. 390개를 채웠다는 이유만으로 즉시 승급하지 않고 매일 **07:00 KST에 판정한 다음** 다음 대결을 준비합니다. 두 장기 운영 계좌는 유지하고 시험 계좌만 새 시드로 시작합니다. 학습은 시험 중에도 계속합니다. 점수는 KRW와 USD 각각의 시드 대비 수익률을 합한 값이며 두 통화의 금액을 환율 없이 더한 값이 아닙니다.

재시작은 RAM 시험본을 무효화하므로 새 시험을 시작하며, 남은 하루의 관측이 부족하면 승급하지 않습니다. PC가 꺼져 있던 하루를 관측했다고 취급하지 않습니다. 일일 판정은 운영 계좌의 현금·보유량·목표 기록·미완료 경험을 초기화하지 않습니다. 사용자가 수동으로 초기화할 때만 이전 미완료 경험의 손익 기준을 이전 계좌 값에 고정해 새 시드가 가짜 학습 수익으로 들어가지 않게 합니다. 모델 파일과 미학습 replay는 유지하고, 일일 판정 시 누적 통계는 같은 JSON의 최대 31개 작은 요약으로 보관합니다. 시험 계좌를 중간에 새 시드로 덮어쓰지 않습니다.

장기 보조 입력에는 완료된 **20·60·120·252·504·600·1,260일**, **104·260주**, **36·60개월** 요약을 사용합니다. 기존 보조 입력의 순서는 유지하고 새 연결은 0으로 시작합니다. 추가로 작은 학습 가능한 일봉 인코더가 **종목별 최대 1,300개 완료 일봉을 전부 읽어** 현재 판단에 장기 기억을 붙입니다. 가격·거래량 각 일봉을 실제로 입력하며 5년 수익률 숫자 하나만 대신 넣는 구조가 아닙니다. 일봉 DB는 종목별 최대 1,500개를 저장하고 최초 부족분은 공급자 10년 조회에서 확보합니다. 새 일봉 또는 인코더 가중치가 달라질 때 기억을 다시 계산하고 같은 상태에서는 캐시를 재사용합니다. 본체 입력 길이는 128칸입니다. 상장 기간·공급자 한계 때문에 5년을 확보하지 못한 종목은 실제 일봉 수와 기간을 표시하며, 없었던 과거를 채워 넣지 않습니다.

화면에는 최근 입력 가용성, 고정 시험본의 두 버전과 조건별 통과 여부, 다음 승급전 판정 시각, 판정 사유, 최근 일일 요약을 표시합니다. 보유시간과 매도 체결 승률은 계측 추가 이후의 기록을 기준으로 합니다. 과거 진입 시각이 없는 종목은 보유시간을 추정하지 않습니다.

운영 흐름은 다음과 같습니다.

`공통 시장 관찰 → Champion·Candidate 각자 판단과 가상체결 → 각자 비용을 반영한 계좌 순손익 → 하나의 공통 replay에 저장 → 양쪽의 경험을 두 모델이 각각 batch 학습 → 고정 시험본끼리 하루 승급전 → 이익을 내고 Champion을 이긴 Candidate 시험본만 승급`

- **Champion**은 실시간 시장 판단과 운영용 가상계좌를 담당하며 replay도 학습합니다. 학습은 별도 작업본에서 수행하고 저장이 끝난 가중치를 판단 모델로 교체합니다. 사용자 요청에 따라 Champion 자체 학습을 활성화했으며, 이 갱신 횟수와 Candidate 승급 횟수는 구분합니다.
- **Candidate**도 같은 공통 시장을 필수로 관찰하고 자기 행동·가상계좌 결과를 경험으로 생성합니다. 각자 생성한 경험은 같은 replay에 합쳐 두 모델 모두 학습합니다. 운영 중 계속 바뀌는 두 계좌의 누적 성적은 별도의 고정본 승급 판정에 사용하지 않습니다.
- 같은 GPU에서 두 모델의 학습 회차를 번갈아 처리합니다. 각각 batch 256·optimizer 최대 8회·회차당 최대 2,048개 경험을 사용하며, 잔여 경험이 적으면 작은 batch도 처리합니다. 같은 시장·계좌 입력의 여러 종목 손실을 하나의 본체 계산에 합칩니다. 256개 시장 화면을 동시에 GPU에 올리는 방식이 아니라 공통 입력 하나씩 gradient를 누적합니다. GPU를 공유하므로 두 모델 학습이 처리 속도 두 배를 뜻하지 않습니다. 설정은 `configs/online_learning.json`에서 읽고 실제 완료한 경험·optimizer 수·계산 시간·VRAM은 화면의 최근 학습 회차로 확인합니다.
- 두 운영 계좌는 같은 입력·paper 체결·비용·탐험 확률·난수 추첨을 사용하며, 각자의 현금·보유·가중치·행동·손익은 독립입니다. Candidate의 미처리 관찰은 같은 SQLite에 입력을 남겨 순서대로 처리합니다. 대기열 크기나 오래됐다는 이유로 버리지 않고 재시작 뒤에도 복구합니다. 계좌와 미성숙 경험을 DB에 함께 확정한 뒤 해당 관찰만 제거합니다. 화면에는 새 구조의 공통 관찰 수·각 모델 완료 수·처리 대기·각 계좌의 경험 생성 수를 표시합니다. 과거 방식의 건너뜀 횟수는 역사적 수치로 분리합니다.
- BUY/HOLD/SELL은 모델이 출력한 정책 확률을 사용합니다. 종목 수만으로 HOLD 점수를 덧붙여 매수를 막는 처리는 사용하지 않습니다. 경험 수집에는 명시된 탐험 확률을 적용하고, 검증은 최고 확률 행동을 사용합니다. 보유 종목의 SELL 판단은 배분 점수와 충돌해도 실제 수량을 줄이도록 주문합니다.
- 온라인 강화학습에는 실제 paper 계좌의 종목 손익·계좌 손익 경험을 사용합니다. 독립 BUY/SELL 가격 예측 보상은 진단용이며 계좌 학습 replay에는 넣지 않습니다.
- paper 계좌가 매매할 수 없는 지수·환율 등은 모든 판단의 시장 문맥 입력에 포함합니다. 거래 가능한 종목은 새 관측마다 매수·관망·매도 판단을 저장합니다. 미보유 관망과 주문 미체결도 실제 거래 결과가 0인 경험으로 남기며, 가상의 체결 손익을 만들어 넣지 않습니다.
- 손익은 각 통화의 시드머니 대비 수익률로 저장하고, 두 모델의 최적화에서는 백분율 단위로 환산해 거래비용 신호가 행동 엔트로피에 묻히지 않게 합니다.
- paper 주문은 판단 다음 완료 bar에서 체결됩니다. 해당 거래의 손익 평가 기간은 연결된 체결 bar부터 시작해 설정된 bar/시간이 지난 뒤 끝납니다. 미체결 판단도 경험에 남기되 종목 거래 보상은 0으로 계산하고, 실행되지 않은 주문에 정책·배분의 거래 수익을 부여하지 않습니다.
- **정식 승급 대결**은 검증 시작 시 두 모델을 RAM에 고정해 별도 가상계좌로 비교합니다. 두 모델은 같은 시작 자금·PaperAccount 체결 규칙·수수료·세금·스프레드·슬리피지와, 고정 직후부터 새로 들어온 서로 다른 최소 390개 시장 분 시각을 사용합니다. 각 시각마다 1·3·5·15·60분봉과 일·주·월봉 입력을 양쪽에 똑같이 제공합니다. 대결에서는 양쪽 모두 탐험 없이 가장 높은 확률의 행동을 선택합니다. 종목별 체결 시각이 몰려도 같은 시장 분을 여러 봉으로 세지 않습니다. Candidate 시험본이 Champion 시험본보다 비용 차감 순수익에서 이긴 경우에만 승급합니다. 이것은 기록된 두 시험본 버전의 비교이며 계속 학습 중인 최신 가중치의 승패를 뜻하지 않습니다. 별도 승급으로 기준이 교체되거나 대결 조건이 깨지면 결과는 무효입니다.
- 검증 시작 시 **Champion과 Candidate 둘 다 RAM에 고정**합니다. 원래 두 모델은 검증 중에도 계속 학습하지만 시험본은 바뀌지 않습니다. Champion 자체 학습으로 가중치가 바뀌어도 고정 시험본끼리의 비교는 유지합니다. 별도 승급으로 기준이 교체되면 진행 중 시험은 무효입니다. 다음 시험은 최신 두 모델을 다시 고정한 이후의 새로운 구간에서 시작합니다.
- 시험본이 이기지 못하면 Champion을 유지하고 시험본만 버립니다. 계속 학습 중인 Candidate는 유지합니다. 재시작하면 RAM 시험본의 시험을 무효 처리하고 새로운 미래 구간으로 다시 시작합니다.
- 유효 replay는 오래된 경험부터 순서대로 **두 모델이 각각 정확히 1회** batch 학습합니다. 동일 모델이 같은 경험을 두 번 반복하는 종전 설정은 사용하지 않습니다. 새 경험·시세가 들어오지 않아도 남은 경험과 작은 잔여 batch를 처리합니다. 각 모델 체크포인트에 해당 행의 완료 횟수를 먼저 저장한 뒤 DB에 반영하고, **두 모델 모두 학습과 저장을 끝낸 행만 삭제**합니다. 재시작 시 저장된 완료 횟수를 복구해 정상 완료 경험을 다시 학습하지 않습니다. 체크포인트 저장 전 비정상 종료된 계산은 미완료로 남아 재시도할 수 있습니다. 승급 성공 여부는 학습 경험 삭제 조건이 아닙니다. 입력이 맞지 않는 행은 삭제 대신 보류하며 학습 가능한 미학습 수와 따로 표시합니다.
- 실주문은 기본 OFF입니다. 사용자가 명시적으로 켜기 전까지 실제 주문을 내지 않습니다.
- 시장 추론과 두 모델의 학습 작업은 분리합니다. 학습 중 변경하는 Champion 작업본을 실시간 판단에 직접 사용하지 않습니다. 같은 GPU를 공유하므로 계산 경쟁에 따른 지연은 실제 측정값으로 확인합니다.
- 화면에는 새 경험 수와 별도로 남은 학습 가능한 replay, 진행 중 optimizer 단계·처리 경험 수, 고정 시험본의 검증 진행을 표시합니다. 검증 중이라는 이유로 Candidate 학습이 중단된 것으로 표시하지 않습니다.
- API의 `candidate_learning_enabled`는 학습 루프 활성 상태이며 `candidate_start_ready`는 학습 가능한 경험이 남아 있는 상태입니다. 장 종료나 실시간 시세 대기 때문에 남은 학습을 멈추지 않습니다.
- 정지·재시작 요청 시 학습 중인 모델은 진행 중 optimizer 단계까지만 완료한 뒤 실제 갱신된 가중치와 해당 모델의 replay 사용 횟수를 저장합니다. 정지 요청 후 다음 단계를 추가로 시작하지 않습니다.

## 하루 전체 경험의 순차 학습

### 운영 화면에서 계좌와 모델을 읽는 방법

- Champion과 Candidate 관찰 계좌는 같은 계산식으로 **비용 차감 순손익·시드 대비 수익률·순자산·현금 비중·최대 종목 비중·체결 건수·보유 종목 수**를 표시합니다. KRW와 USD를 환율 없이 합치지 않습니다. 체결이 없는 계좌는 성과 평가 전으로 표시합니다.
- 두 누적 관찰 계좌는 승급 점수가 아닙니다. Candidate의 관찰 누락, 계좌 시각, 저장된 관찰 버전을 함께 확인하고, 승급 결과는 고정된 두 시험본의 정식 하루 승급전 대결에서 확인합니다.
- 손실 원인을 구분하도록 누적 수수료·세금·스프레드·슬리피지와 실현·평가손익을 표시합니다. `순손익 + 기록된 비용`은 같은 체결 기록의 비용 합산 설명이며, 비용을 없애고 다시 거래한 성과가 아닙니다. 순손익과 실현·평가손익 합계의 일치 여부도 확인합니다.
- 접이식 상세 패널에는 종목 이름·수량·평단·평가가격·계좌 비중·평가손익, 최근 최대 200개 체결, 현재 새 시세가 있는 거래 가능 종목의 매수·관망·매도 확률과 행동, 주문 제출 여부, 통화별 현금 목표를 표시합니다. 새 주문과 실제 체결은 구분하며, 없는 정책 지표를 오래된 판단으로 대신 채우지 않습니다.
- 평균 최고 행동 확률과 확률 퍼짐은 이미 계산한 출력의 진단값입니다. 확률 퍼짐 100%는 세 행동 확률이 같다는 뜻이며 모델의 수익성 점수가 아닙니다. 확률 추첨이 최고 확률 행동과 달라진 횟수도 표시합니다. 계좌 진단을 위해 모델 추론을 추가 실행하지 않습니다.
- 정책 진단은 현재 관측과 마지막 거래 가능 관측 한 개만 보관하며 이력을 계속 쌓지 않습니다. 장외 시간에는 마지막 기록의 시각을 명시합니다. 양쪽 계좌에 누적 추론 횟수·최근 추론 시간·관찰 대기열 건너뜀·대기 주문 수도 같은 형식으로 표시합니다.
- **현재 환경의 한계:** 키움 원본 체결 틱도 1분봉으로 집계하고, 여러 시간봉의 요약을 사용합니다. 최우선 매수·매도 호가가 있는 종목 수를 표시하지만 전체 호가 단계·대기열·실제 체결 유동성은 재현하지 않습니다. 1초 단타의 수익성을 검증한 환경은 아닙니다. 15초·30초·1초 데이터를 추가한다고 수익 개선이 보장되지 않습니다.
- 운영 계좌에서는 정책 확률에 따라 행동을 추첨하며 하루 승급전에서는 최고 확률 행동을 선택합니다. 두 독립 계좌가 만든 행동·손익 경험을 공통 replay에 합쳐 두 모델이 각각 학습합니다. 현재 결과 평가 간격은 입력 시간봉과 별도이며 화면에 실행 설정값을 표시합니다.

관찰 종목의 첫 확대는 사용자 선택대로 한국 25개·미국 25개를 추가한 **총 222개(주식 194개·문맥 28개)**입니다. 추가 종목은 제공처의 실제 종목·통화를 확인했으며 기존 ID를 바꾸지 않고 새로운 한국 종목에만 전용 ID를 뒤에 붙입니다. 신규 ID 행은 해당 지역 기존 임베딩 평균으로 시작하며 기존 가중치 행은 보존합니다. API와 화면의 처리량 상세에는 확대 직전 측정과 현재 수신·입력 수·추론 시간·학습량·실제 계산 시간·VRAM·미학습 적체를 함께 표시합니다. GPU의 순간 사용률만으로 여유나 처리량을 단정하지 않습니다.

키움 실전 시세는 공식 주식체결 `0B` 명세의 통합 거래소 코드 `_AL`을 사용합니다. 한국 105종목을 KRX/NXT 각각 등록해 210개로 요청하던 방식은 세션 등록 한도 200개를 넘어 거부되어, 종목당 하나인 통합 코드 105개로 수정했습니다. `15` 체결량 필드의 매수 `+`·매도 `-` 부호도 보존해 분봉의 매수·매도 체결량을 계산합니다. 전체 호가 잔량은 아직 수집하지 않으며 0을 실제 잔량으로 꾸며 표시하지 않습니다. 근거: [키움 공식 API 명세](https://github.com/Kiwoom-Securities/Kiwoom-REST-API/blob/main/kiwoom/_data/kiwoom_api_spec.json), [세션별 시세 등록 한도](https://openapi2.kiwoom.com/intro?dummyVal=0).
- 이번 화면 정리는 계측과 표시 수정입니다. 임의 보유 종목 상한, 수수료 완화, 계좌 초기화, 모델 가중치 교체를 추가하지 않습니다.

현재 우선순위는 수집된 유효 경험을 빠뜨리지 않고 학습하는 것입니다. **입력 길이 128칸은 하루에 배우는 경험 수 제한이 아닙니다.** `1~128 → 2~129 → 3~130`처럼 입력 창을 옮기며 수집된 하루 전체를 처리합니다. 하루 승급전도 별도의 평가 길이이며 학습량 제한이 아닙니다.

- 같은 시장·계좌 입력을 공유하는 종목 경험은 Transformer 입력 계산을 공유하고 각 경험의 손실을 모두 합산합니다. 종목이나 경험을 일부 버려 계산량을 줄이지 않습니다.
- 겹치는 입력 창은 같은 SQLite의 압축된 프레임을 공유합니다. replay DB를 하나 더 만들거나 경험용 `.pt` 파일을 만들지 않습니다.
- 아직 결과가 나오지 않은 판단도 당시 입력과 함께 같은 DB에 저장합니다. 재시작·주말·장 마감으로 만료시키지 않습니다. 재시작 후 남은 경험과 사용 횟수를 복구합니다.
- 장중 학습이 수집을 따라가지 못하면 남은 경험을 보존하고 장 마감·주말에도 학습합니다. 시스템과 컴퓨터가 켜져 있어야 진행됩니다. 주말에 전부 끝날지는 실제 수집량과 학습 속도로 판단합니다.
- 용량이 커졌다는 이유로 학습 전 경험을 삭제하거나 4,096건에서 잘라내지 않습니다. 50 MiB는 저장량 알림 기준이며 삭제·쓰기 제한이 아닙니다. 미학습 분량이 쌓이는 동안 용량은 늘어날 수 있습니다.
- 운영실에 한국시간 기준 날짜별 생성량·두 모델의 1회 이상 학습량·학습 및 저장 완료량·남은 학습 가능 분량·완료율을 표시합니다. 평가 대기·학습 불가·보류는 따로 표시합니다. 이전 단일 모델과 2회 반복 설정으로 완료된 과거 집계는 당시 기준을 유지하며, 이미 삭제된 경험을 다시 배웠다고 주장하지 않습니다. 1회 기준으로 전환할 때 이미 양쪽 체크포인트 저장이 확인된 잔여 행만 완료 처리합니다.
- 경험 1건은 종목·판단 시점·보상 종류로 구분합니다. 종목 손익과 계좌 배분 보상은 서로 다른 학습 목표이며 하나로 없애지 않습니다. 서로 다른 시점의 겹치는 128칸 입력도 별도 경험으로 유지합니다. 같은 입력의 여러 종목 계산과 겹치는 프레임 저장만 공유합니다.

현재 수집 범위는 공급자가 실제 제공한 봉·시세입니다. ITCH의 모든 개별 호가·체결 메시지를 수집·학습한다고 주장하지 않습니다. 공급자 누락과 아직 완료되지 않은 보상은 완료된 학습량과 구분합니다.

## 모델

글로벌 Transformer는 시간축과 여러 종목·시장 문맥을 함께 처리합니다. 설계 목표는 약 0.5B 파라미터 규모이며, 체크포인트에 따라 실제 구조와 크기가 다를 수 있습니다. 시간축 128칸은 종목 수 제한을 뜻하지 않습니다. GRU와 teacher 기반 학습은 초기 비교·부트스트랩 연구입니다.

종목별 시세 시각이 다르므로 각 종목의 입력 창 안에서 마지막 유효 관측의 출력 상태를 사용합니다. 최신 공통 시각에 새 시세가 없는 종목의 과거 관측을 0으로 버리지 않습니다. 추론과 활성화 재계산을 사용하는 두 모델의 학습은 같은 출력 규칙을 적용합니다.

실시간 판단의 본체 입력은 **최근 수집 시점 128칸**입니다. 공급자가 분봉과 초 단위 체결을 함께 보내면 128칸이 정확히 128분을 뜻하지 않습니다. 여기에 `1m·3m·5m·15m·60m·1d·1w·1mo`의 완료된 봉에서 만든 종목별 보조 입력을 한 번에 붙입니다. 각 시간봉에는 최근 변화, 해당 시간축의 긴 구간 변화, 가격 범위, 거래량 변화, 최신성, 확보된 기록 비율을 구분해 넣습니다. 긴 구간은 일봉 64개·주봉 52개·월봉 24개이며, 기록이 부족하면 해당 값과 확보 비율로 부족함을 드러냅니다. 큰 Transformer를 시간봉마다 반복 실행하지 않고 작은 학습 가능한 보조층이 정보를 합칩니다.
기존 `time_scale_embedding`의 크기는 바꾸지 않습니다. 세부 시간봉은 보조 입력의 고정된 순서로 구분하므로 종전 체크포인트를 읽을 수 있습니다.

기존 Champion/Candidate 가중치 형식은 유지합니다. 새 보조층은 처음에는 출력이 0이어서 기존 판단을 바꾸지 않고, 이후 실제 paper 경험으로 두 모델이 각각 학습합니다. Candidate의 Champion 교체는 동일한 미래 구간 승급 검증을 통과해야 합니다. `configs/live_symbols_korea.json`의 `decision_timeframes` 순서는 모델 입력 순서와 일치해야 합니다.
`/api/status`의 `metrics.multiscale_coverage`는 시간봉별 실제 입력 기록 확보 비율을 보여줍니다. 장기 일봉 기록이 아직 수집되지 않았다면 주봉·월봉 수치는 0에 가깝습니다.
운영 화면의 **모델 판단 입력**은 `1·3·5·15·60분봉 + 일·주·월봉 통합 판단`으로 표시합니다. 단일 시간 선택창은 제거했습니다. 매번 확보된 여러 시간봉의 완료 데이터를 함께 사용하며, 시간봉별 실제 확보 상태는 위 지표로 확인합니다. 이 화면 변경은 내부 보상 평가 기간이나 학습·승급 설정을 변경하지 않습니다.

## 운영 확인과 백테스트

운영실의 **전체 경험 학습 현황 · 모델 교체 기준**에 두 모델 각각의 optimizer 진행·처리한 replay·학습 및 저장 완료 회차·마지막 완료 시각·남은 경험과, 검증 진행·시세 지연·오류를 표시합니다. 마지막 완료 학습량과 시간·프로세스 peak VRAM은 다음 회차 도중에도 유지합니다. **모든 시간봉 입력 · 실제 확보와 학습 사용** 표는 8개 시간축 각각의 입력 기록 확보율·데이터가 있는 종목 수·기록이 충분한 종목 수·양쪽 최근 완료 학습에 포함된 경험 수를 보여줍니다. 장기 시간봉은 보조층에 요약 입력하며 과거 일·주·월봉 전체를 별도 경험으로 전수 학습했다고 표시하지 않습니다. 완료율은 수집 후 보상 평가를 마쳐 저장된 경험을 기준으로 하며, 전체 시장의 모든 체결 수집률을 뜻하지 않습니다.

백테스트는 운영·승급 검증과 같은 `PaperAccount`를 사용합니다. 현금, 보유량, 추가매수·부분매도, 판단 다음 관측에서의 체결, 수수료·매도세 가정·스프레드·슬리피지를 반영한 순자산 성과를 계산합니다. KRW와 USD의 실제 금액을 합산하지 않고 각 시드머니로 정규화한 수익률을 비교합니다. 같은 데이터에서 추론을 두 번 수행하지 않습니다. 과거 진단 백테스트는 학습 이력이 따로 확인되지 않는 한 미학습 구간 성과라고 주장하지 않습니다. 승급은 별도의 미래 시험으로만 결정합니다.

현재 직접 가상매매 가능한 자산은 주식·ETF이며 나머지는 시장 문맥입니다. 키움 체결의 최우선 매수·매도 호가는 입력할 수 있지만 전체 호가 잔량을 지원한다고 주장하지 않습니다. 실제 매매 수익 개선은 학습 횟수나 가중치 변경만으로 확정할 수 없으며, 동일 미래 계좌 비교 결과로 확인합니다.

검증 대기열은 전체 시장 이력을 복제하지 않고 최근 입력 창만 담는 RAM 관측본 32개로 제한합니다. 두 모델 학습의 optimizer batch와 시험본·관찰본의 GPU 이동은 같은 자원 잠금으로 조율합니다. Champion 추론은 독립적으로 계속합니다. JSON 상태 저장은 파일별 쓰기를 직렬화하고 짧은 Windows 공유 충돌을 재시도합니다.

관련 회귀 확인은 프로젝트 루트에서 `python -m unittest discover -s tests -v`로 실행합니다.

## 실행

Windows에서 프로젝트 루트의 `StockRL Start.bat`을 실행합니다. 로컬 운영 화면은 `http://127.0.0.1:8766/`, 상태 API는 `http://127.0.0.1:8766/api/status`입니다. 실행 중 상태는 API에서 확인하며, 과거 저장 지표만으로 현재 작동 여부를 판단하지 않습니다.

Python 3.10 이상과 실행 환경에 맞는 PyTorch가 필요합니다.

```powershell
python -m pip install -e .
```

## 파일과 저장 공간

- **소스·설정·문서:** 이 Git 프로젝트에 둡니다.
- **모델 가중치:** `champion.pt`, `candidate.pt`는 Hugging Face에 보관합니다. 모델 가중치만 GitHub 업로드 대상에서 제외합니다.
- **운영 데이터:** 프로젝트 안의 `runtime/markets/<market>/live`에 둡니다. runtime을 포함한 프로젝트 파일을 GitHub에 함께 저장해 다른 컴퓨터에서 프로젝트를 내려받으면 paper 계좌·replay·cursor·시세 데이터까지 이어받도록 합니다.
- **여러 시간봉 기록:** 1분봉은 기존 `market.csv`를 사용하고, 완료된 일봉은 같은 runtime의 `timeframes.sqlite3` 한 파일에 종목당 최근 600개까지만 보관합니다. DB 본문에는 32 MiB 상한을 둡니다. 3·5·15·60분봉은 최근 1분봉으로, 주봉·월봉은 이 일봉 기록으로 만듭니다. 아직 완성되지 않은 상위 봉과 판단 시점 이후 데이터는 입력하지 않습니다.
- **저장 공간:** 판단·오류·실행 기록은 정해진 크기에 닿으면 같은 파일을 비우고 새 기록을 씁니다. 시세 cache는 저장 cursor 이후의 미처리 봉과 필요한 입력 문맥을 보존합니다. replay는 두 모델 모두 학습과 저장이 끝난 행만 삭제하고 빈 공간을 회수합니다. 미학습 데이터 보존을 저장 용량 한도보다 우선하므로 밀린 분량이 많으면 runtime이 과거 100 MiB 목표를 넘을 수 있습니다. 필요하면 사용자가 허용한 모델 폴더로 학습 DB만 옮길 수 있습니다. 날짜별 snapshot/archive 복사본은 만들지 않습니다.
- **판단 집계:** `decisions.csv`는 열 제목줄을 포함해 저장합니다. 대시보드의 BUY/HOLD/SELL 건수는 이 파일의 최신 종목별 판단을 집계합니다.
- **대시보드:** `src/stockrl/web_dashboard.html`이 기준 파일입니다. 하드디스크에 별도 HTML 백업 파일이나 백업 폴더를 만들지 않습니다. 수정 전 현재 프로젝트를 GitHub에 commit·push하고 원격 저장을 확인한 뒤 수정합니다.
- **가상계좌 초기화:** 운영 제어의 서버 재시작 버튼 옆 `계좌 초기화`는 Champion 운영 계좌와 Candidate 관찰 계좌의 시드머니·보유 종목·체결·누적 손익을 초기화하고, Champion의 최근 판단 방향 기록도 비웁니다. 모델 가중치와 replay는 유지합니다. 실행 중이면 학습·시세 상태를 저장한 뒤 시스템을 다시 시작하며, 새 판단이 들어오면 방향 기록이 다시 쌓입니다. 진행 중인 승급 검증은 재시작 시 무효 처리됩니다.
- **Git 제외:** `.pt`, `.pth`, `.ckpt`, `.safetensors` 모델 가중치만 제외합니다. 그 밖의 프로젝트 파일과 runtime 파일은 제외하지 않습니다. GitHub 파일 하나가 100MB를 넘지 않도록 유지합니다.

## 데이터·연구 도구

ITCH, FI-2010, FinRL, TradeMaster, MacroHFT 등 공개 시장 데이터와 연구 코드는 선행학습·비교 실험의 재료입니다. `scripts/`와 연구용 모듈의 결과가 운영 Champion에 자동 적용되지는 않습니다. 모든 학습과 비교는 시간순 데이터를 사용하고 미래 정보 누수를 피해야 합니다.

## 현재 상태 확인

`GET /api/status`에서 feed와 agent 진행 상태, 두 모델 각각의 학습·optimizer 갱신·계산 시간·peak VRAM·남은 경험, replay 건수, 검증 bar, 승급·거절, Champion과 Candidate 계좌 및 실제 주문 OFF 상태를 확인합니다. 프로세스가 살아 있다는 표시만으로 판단이나 학습이 진행 중이라고 보지 않습니다.

현재 실행기는 `configs/live_symbols_korea.json`을 사용합니다. 별도 `configs/live_symbols.json`의 종목 수를 운영 수로 보지 않습니다. 화면에는 등록·최근 수신·실제 모델 입력·종목 ID 미연결 수를 구분합니다. `max_symbols`는 종목 ID 공간이며 해당 수의 종목을 GPU에 동시에 처리할 수 있다는 보장이 아닙니다. 새 종목은 체크포인트의 종목 ID 연결과 공급자 수신을 먼저 확인해야 합니다. 완료된 장기 봉의 내용이 같아도 새 단기 관측·손익 경험에는 장기 문맥을 계속 함께 입력합니다.

## 라이선스와 안전

이 프로젝트는 연구·엔지니어링 도구이며 수익을 보장하거나 투자 조언을 제공하지 않습니다. 기본 운용은 paper trading입니다. 사용자의 명시적인 설정 없이는 실주문을 실행하지 않습니다.

## 과거 연구 기록

초기 연구에는 가중 teacher 앙상블, GRU actor-critic, teacher 증류, PPO, 과거 checkpoint와 benchmark가 포함됩니다. 이는 프로젝트의 역사적 실험이며 현재 자율 지속학습 운영 구조와 구분합니다. 과거 실험 결과는 현재 모델의 성능이나 승급 근거로 간주하지 않습니다.

## 실행 중 수정과 GPU 학습 최적화

- HTML/CSS/JS 수정은 브라우저 새로고침으로 적용합니다.
- 웹서버 재시작은 기존 feed/agent PID와 모델 메모리를 유지합니다. 전체 정지는 별도 동작입니다.
- `configs/online_learning.json`의 batch, optimizer 횟수, GPU 우선순위, 새 경험의 보상 연결 길이는 학습·저장 완료 후 다음 회차부터 재적용됩니다. 기존 replay 보상과 진행 중 승급전 조건은 유지합니다.
- `online/learning.py`의 학습 계산과 `online/losses.py`는 완료된 학습 회차 사이에서 재적용됩니다. 잘못된 설정이나 Python 문법은 거부하고 마지막 정상 상태를 유지합니다. 모델 구조·활성 계좌 목표 변경은 별도 마이그레이션 대상입니다.
- `/api/runtime`은 실행 모드, 설정·코드 적용 상태와 GPU 작업을 가볍게 조회합니다. 대시보드의 입력·계측 상세에서도 적용값·보류·오류를 확인할 수 있습니다.
- GPU 학습은 공유 입력의 경험 손실을 벡터 연산으로 계산하고 fused AdamW를 사용합니다. 각 모델의 경험당 학습 횟수, 보상, rolling 입력, 저장 후 삭제 규칙은 유지합니다.
