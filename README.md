# 자가성장형 온라인 강화학습 트레이딩 에이전트

저장소 이름은 **Continual Trading Agent**입니다.

시장의 경험과 거래 비용을 뺀 순손익으로 정책을 계속 발전시키는 자율 강화학습 트레이딩 에이전트입니다.

## 프로젝트 목표

이 프로젝트는 특정 trader나 고정 전략을 영구 모방하는 모델이 아닙니다. 모델은 시장, 종목, 시간축, 포트폴리오 상태를 바탕으로 종목 선택, BUY/HOLD/SELL, 자금 배분, 포지션 유지·증감·교체·청산을 경험으로 학습합니다.

Teacher 모델, 공개 모델, 과거 trader 기록은 초기 금융 문법을 익히는 교육 재료입니다. 최종 목표는 이 자료를 그대로 복사하는 것이 아니라 시장 경험과 보상을 통해 모델 자신의 정책을 발전시키는 것입니다.

수수료, 거래세, 슬리피지, 스프레드, 현금, 보유량, 평단, 실현·평가 손익, 유동성, 자본 규모와 체결 규칙은 환경이 계산합니다. 구체적인 매매전략과 자금 배분은 모델이 경험으로 발견합니다.

## 학습과 승급

운영 흐름은 다음과 같습니다.

`시장 관찰 → Champion 판단과 가상체결 → 비용을 반영한 계좌 순손익 → replay 저장 → Candidate batch 학습 → Champion과 같은 미래 paper 구간에서 비교 → 나을 때만 승급`

- **Champion**은 현재 기준 모델이며, 실시간 시장 판단과 운영용 가상계좌를 담당합니다.
- **Candidate**는 Champion에서 시작해 replay 경험을 학습합니다. Candidate 관찰용 가상계좌는 학습 중 행동을 보는 용도이며 승급 판정에는 쓰지 않습니다.
- Candidate 관찰과 승급 검증은 모델의 가장 높은 확률 행동을 사용하며 탐험 추첨을 섞지 않습니다. Champion의 온라인 경험 수집에는 설정된 탐험이 유지됩니다.
- 종목 수가 많고 BUY/HOLD/SELL 점수가 비슷할 때, 미보유 종목은 종목 수에 비례한 관망 기준을 적용합니다. Champion의 탐험 확률도 종목 수에 맞춰 줄여 근거 없는 동시 매수를 억제합니다. 보유 종목의 SELL 판단은 배분 점수와 충돌해도 실제 수량을 줄이도록 주문합니다.
- 온라인 강화학습에는 실제 paper 계좌의 종목 손익·계좌 손익 경험을 사용합니다. 독립 BUY/SELL 가격 예측 보상은 진단용이며 계좌 학습 replay에는 넣지 않습니다.
- paper 계좌가 매매할 수 없는 지수·환율 등은 시장 문맥으로만 보고, 매매 경험 replay에는 넣지 않습니다. 미보유 종목의 관망도 대량의 무의미한 0원 거래 경험으로 저장하지 않습니다.
- 손익은 각 통화의 시드머니 대비 수익률로 저장하고, Candidate 최적화에서는 백분율 단위로 환산해 거래비용 신호가 행동 엔트로피에 묻히지 않게 합니다.
- paper 주문은 판단 다음 완료 bar에서 체결됩니다. 해당 거래의 손익 평가 기간은 연결된 체결 bar부터 시작해 설정된 bar/시간이 지난 뒤 끝나며, 미체결 주문은 거래 손익 경험으로 학습하지 않습니다.
- **승급 검증**은 검증 시점의 Candidate를 고정해 Champion과 같은 미래 데이터, 출발 자금, 계좌 규칙, 비용으로 비교합니다. 현재 기준은 128개 bar이며, Candidate가 비용 차감 순수익에서 이긴 경우에만 승급합니다. 검증 구간에서 Champion이 바뀌면 해당 비교는 무효입니다.
- Candidate가 이기지 못하면 Champion을 유지하고 Candidate를 현재 Champion 기준으로 다시 시작합니다.
- 실주문은 기본 OFF입니다. 사용자가 명시적으로 켜기 전까지 실제 주문을 내지 않습니다.
- 시장 추론과 Candidate 학습은 분리해 학습이 시세 관찰을 막지 않도록 합니다.

## 모델

글로벌 Transformer는 시간축과 여러 종목·시장 문맥을 함께 처리합니다. 설계 목표는 약 0.5B 파라미터 규모이며, 체크포인트에 따라 실제 구조와 크기가 다를 수 있습니다. 시간축 128칸은 종목 수 제한을 뜻하지 않습니다. GRU와 teacher 기반 학습은 초기 비교·부트스트랩 연구입니다.

실시간 판단의 본체 입력은 **1분봉 128개**입니다. 여기에 `1m·3m·5m·15m·60m·1d·1w·1mo`의 완료된 봉에서 만든 종목별 보조 입력을 한 번에 붙입니다. 각 시간봉에는 최근 변화, 해당 시간축의 긴 구간 변화, 가격 범위, 거래량 변화, 최신성, 확보된 기록 비율을 구분해 넣습니다. 긴 구간은 일봉 64개·주봉 52개·월봉 24개이며, 기록이 부족하면 해당 값과 확보 비율로 부족함을 드러냅니다. 큰 Transformer를 시간봉마다 반복 실행하지 않고 작은 학습 가능한 보조층이 정보를 합칩니다.
기존 `time_scale_embedding`의 크기는 바꾸지 않습니다. 세부 시간봉은 보조 입력의 고정된 순서로 구분하므로 종전 체크포인트를 읽을 수 있습니다.

기존 Champion/Candidate 가중치 형식은 유지합니다. 새 보조층은 처음에는 출력이 0이어서 기존 판단을 바꾸지 않고, 이후 실제 paper 경험으로 Candidate가 학습한 뒤 동일한 미래 구간 승급 검증을 통과해야 Champion에 반영됩니다. `configs/live_symbols_korea.json`의 `decision_timeframes` 순서는 모델 입력 순서와 일치해야 합니다.
`/api/status`의 `metrics.multiscale_coverage`는 시간봉별 실제 입력 기록 확보 비율을 보여줍니다. 장기 일봉 기록이 아직 수집되지 않았다면 주봉·월봉 수치는 0에 가깝습니다.

## 실행

Windows에서 프로젝트 루트의 `StockRL Start.bat`을 실행합니다. 로컬 운영 화면은 `http://127.0.0.1:8766/`, 상태 API는 `http://127.0.0.1:8766/api/status`입니다. 실행 중 상태는 API에서 확인하며, 과거 저장 지표만으로 현재 작동 여부를 판단하지 않습니다.

Python 3.10 이상과 실행 환경에 맞는 PyTorch가 필요합니다.

```powershell
python -m pip install -e .
```

## 파일과 저장 공간

- **소스·설정·문서:** 이 Git 프로젝트에 둡니다.
- **모델 가중치:** `champion.pt`, `candidate.pt`는 Hugging Face에 보관합니다. 모델 가중치만 GitHub 업로드 대상에서 제외합니다.
- **운영 데이터:** 프로젝트 안의 `runtime/markets/<market>/live`에 둡니다. runtime을 포함한 프로젝트 파일을 GitHub에 함께 저장해 다른 컴퓨터에서 프로젝트를 내려받으면 paper 계좌·replay·cursor·시세 데이터까지 이어받도록 합니다.
- **여러 시간봉 기록:** 1분봉은 기존 `market.csv`를 사용하고, 완료된 일봉은 같은 runtime의 `timeframes.sqlite3` 한 파일에 종목당 최근 600개까지만 보관합니다. DB 본문에는 32 MiB 상한을 둡니다. 3·5·15·60분봉은 최근 1분봉으로, 주봉·월봉은 이 일봉 기록으로 만듭니다. 아직 완성되지 않은 상위 봉과 판단 시점 이후 데이터는 입력하지 않습니다.
- **저장 한도:** runtime은 100 MiB 이하를 목표로 합니다. 판단·오류·실행 기록은 정해진 크기에 닿으면 같은 파일을 비우고 새 기록을 씁니다. 시세 cache와 replay도 제한된 공간에서 순환합니다. 날짜별 runtime snapshot/archive처럼 순차적으로 쌓이는 복사본은 만들지 않습니다. 운영 계좌 상태와 모델 가중치는 용량 정리 때 임의로 지우지 않습니다.
- **판단 집계:** `decisions.csv`는 열 제목줄을 포함해 저장합니다. 대시보드의 BUY/HOLD/SELL 건수는 이 파일의 최신 종목별 판단을 집계합니다.
- **대시보드:** `src/stockrl/web_dashboard.html`이 기준 파일입니다. 하드디스크에 별도 HTML 백업 파일이나 백업 폴더를 만들지 않습니다. 수정 전 현재 프로젝트를 GitHub에 commit·push하고 원격 저장을 확인한 뒤 수정합니다.
- **가상계좌 초기화:** 운영 제어의 서버 재시작 버튼 옆 `계좌 초기화`는 Champion 운영 계좌와 Candidate 관찰 계좌의 시드머니·보유 종목·체결·누적 손익을 초기화하고, Champion의 최근 판단 방향 기록도 비웁니다. 모델 가중치와 replay는 유지합니다. 실행 중이면 학습·시세 상태를 저장한 뒤 시스템을 다시 시작하며, 새 판단이 들어오면 방향 기록이 다시 쌓입니다. 진행 중인 승급 검증은 재시작 시 무효 처리됩니다.
- **Git 제외:** `.pt`, `.pth`, `.ckpt`, `.safetensors` 모델 가중치만 제외합니다. 그 밖의 프로젝트 파일과 runtime 파일은 제외하지 않습니다. GitHub 파일 하나가 100MB를 넘지 않도록 유지합니다.

## 데이터·연구 도구

ITCH, FI-2010, FinRL, TradeMaster, MacroHFT 등 공개 시장 데이터와 연구 코드는 선행학습·비교 실험의 재료입니다. `scripts/`와 연구용 모듈의 결과가 운영 Champion에 자동 적용되지는 않습니다. 모든 학습과 비교는 시간순 데이터를 사용하고 미래 정보 누수를 피해야 합니다.

## 현재 상태 확인

`GET /api/status`에서 feed와 agent 진행 상태, Candidate 학습·optimizer 갱신, replay 건수, 검증 bar, 승급·거절, Champion과 Candidate 계좌 및 실제 주문 OFF 상태를 확인합니다. 프로세스가 살아 있다는 표시만으로 판단이나 학습이 진행 중이라고 보지 않습니다.

## 라이선스와 안전

이 프로젝트는 연구·엔지니어링 도구이며 수익을 보장하거나 투자 조언을 제공하지 않습니다. 기본 운용은 paper trading입니다. 사용자의 명시적인 설정 없이는 실주문을 실행하지 않습니다.

## 과거 연구 기록

초기 연구에는 가중 teacher 앙상블, GRU actor-critic, teacher 증류, PPO, 과거 checkpoint와 benchmark가 포함됩니다. 이는 프로젝트의 역사적 실험이며 현재 자율 지속학습 운영 구조와 구분합니다. 과거 실험 결과는 현재 모델의 성능이나 승급 근거로 간주하지 않습니다.
