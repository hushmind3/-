# 온라인 강화학습 기반 자율 포트폴리오 운용 에이전트

저장소 이름은 **Continual Trading Agent**입니다.

Transformer + Actor-Critic + Continual/Online RL + Portfolio Allocation 구조로, 시장을 관찰하고 현금 포함 자금 배분·진입·유지·청산을 결정하며 비용을 뺀 순자산 결과로 정책을 계속 학습합니다.

## 프로젝트 목표

이 프로젝트는 특정 trader나 고정 전략을 영구 모방하는 모델이 아닙니다. 모델은 시장, 종목, 시간축, 포트폴리오 상태를 바탕으로 종목 선택, BUY/HOLD/SELL, 자금 배분, 포지션 유지·증감·교체·청산을 경험으로 학습합니다.

Teacher 모델, 공개 모델, 과거 trader 기록은 초기 금융 문법을 익히는 교육 재료입니다. 최종 목표는 이 자료를 그대로 복사하는 것이 아니라 시장 경험과 보상을 통해 모델 자신의 정책을 발전시키는 것입니다.

수수료, 거래세, 슬리피지, 스프레드, 현금, 보유량, 평단, 실현·평가 손익, 유동성, 자본 규모와 체결 규칙은 환경이 계산합니다. 구체적인 매매전략과 자금 배분은 모델이 경험으로 발견합니다.

## 학습과 승급

운영 흐름은 다음과 같습니다.

`시장 관찰 → Champion 판단과 가상체결 → 비용을 반영한 계좌 순손익 → 하나의 replay에 저장 → Champion·Candidate 각각 batch 학습 → 두 모델의 고정 시험본을 같은 미래 paper 구간에서 비교 → Candidate 시험본이 나을 때만 승급`

- **Champion**은 실시간 시장 판단과 운영용 가상계좌를 담당하며 replay도 학습합니다. 학습은 별도 작업본에서 수행하고 저장이 끝난 가중치를 판단 모델로 교체합니다. 사용자 요청에 따라 Champion 자체 학습을 활성화했으며, 이 갱신 횟수와 Candidate 승급 횟수는 구분합니다.
- **Candidate**도 같은 replay 경험을 따로 학습합니다. Candidate 관찰용 가상계좌는 학습 중 행동을 보는 용도이며 승급 판정에는 쓰지 않습니다.
- 같은 GPU에서 두 모델의 학습 회차를 번갈아 처리합니다. 각각 batch 8·optimizer 최대 8회·회차당 최대 64개 경험을 사용하며, 잔여 경험이 적으면 작은 batch도 처리합니다. GPU를 공유하므로 두 모델 학습이 처리 속도 두 배를 뜻하지 않습니다.
- Champion 운영 계좌와 Candidate 실시간 관찰 계좌는 같은 paper 계좌 규칙·비용 설정을 씁니다. 같은 시장 봉을 관찰할 때는 양쪽 모두 같은 탐험 확률과 난수 추첨을 사용합니다. Candidate 관찰 대기열이 밀리면 오래된 봉을 건너뛰며, 학습이 끝날 때 관찰에 쓰는 가중치 버전도 바뀔 수 있으므로 두 운영 관찰 계좌의 누적 손익은 공정한 승패 점수가 아닙니다.
- BUY/HOLD/SELL은 모델이 출력한 정책 확률을 사용합니다. 종목 수만으로 HOLD 점수를 덧붙여 매수를 막는 처리는 사용하지 않습니다. 경험 수집에는 명시된 탐험 확률을 적용하고, 검증은 최고 확률 행동을 사용합니다. 보유 종목의 SELL 판단은 배분 점수와 충돌해도 실제 수량을 줄이도록 주문합니다.
- 온라인 강화학습에는 실제 paper 계좌의 종목 손익·계좌 손익 경험을 사용합니다. 독립 BUY/SELL 가격 예측 보상은 진단용이며 계좌 학습 replay에는 넣지 않습니다.
- paper 계좌가 매매할 수 없는 지수·환율 등은 모든 판단의 시장 문맥 입력에 포함합니다. 거래 가능한 종목은 새 관측마다 매수·관망·매도 판단을 저장합니다. 미보유 관망과 주문 미체결도 실제 거래 결과가 0인 경험으로 남기며, 가상의 체결 손익을 만들어 넣지 않습니다.
- 손익은 각 통화의 시드머니 대비 수익률로 저장하고, 두 모델의 최적화에서는 백분율 단위로 환산해 거래비용 신호가 행동 엔트로피에 묻히지 않게 합니다.
- paper 주문은 판단 다음 완료 bar에서 체결됩니다. 해당 거래의 손익 평가 기간은 연결된 체결 bar부터 시작해 설정된 bar/시간이 지난 뒤 끝납니다. 미체결 판단도 경험에 남기되 종목 거래 보상은 0으로 계산하고, 실행되지 않은 주문에 정책·배분의 거래 수익을 부여하지 않습니다.
- **정식 승급 대결**은 검증 시작 시 두 모델을 RAM에 고정해 별도 가상계좌로 비교합니다. 두 모델은 같은 시작 자금·PaperAccount 체결 규칙·수수료·세금·스프레드·슬리피지와, 고정 직후부터 새로 들어온 서로 다른 128개 시장 분 시각을 사용합니다. 각 시각마다 1·3·5·15·60분봉과 일·주·월봉 입력을 양쪽에 똑같이 제공합니다. 대결에서는 양쪽 모두 탐험 없이 가장 높은 확률의 행동을 선택합니다. 종목별 체결 시각이 몰려도 같은 시장 분을 여러 봉으로 세지 않습니다. Candidate 시험본이 Champion 시험본보다 비용 차감 순수익에서 이긴 경우에만 승급합니다. 이것은 기록된 두 시험본 버전의 비교이며 계속 학습 중인 최신 가중치의 승패를 뜻하지 않습니다. 별도 승급으로 기준이 교체되거나 대결 조건이 깨지면 결과는 무효입니다.
- 검증 시작 시 **Champion과 Candidate 둘 다 RAM에 고정**합니다. 원래 두 모델은 검증 중에도 계속 학습하지만 시험본은 바뀌지 않습니다. Champion 자체 학습으로 가중치가 바뀌어도 고정 시험본끼리의 비교는 유지합니다. 별도 승급으로 기준이 교체되면 진행 중 시험은 무효입니다. 다음 시험은 최신 두 모델을 다시 고정한 이후의 새로운 구간에서 시작합니다.
- 시험본이 이기지 못하면 Champion을 유지하고 시험본만 버립니다. 계속 학습 중인 Candidate는 유지합니다. 재시작하면 RAM 시험본의 시험을 무효 처리하고 새로운 미래 구간으로 다시 시작합니다.
- 유효 replay는 오래된 경험부터 순서대로 **두 모델이 각각 2회** batch 학습합니다. 새 경험·시세가 들어오지 않아도 남은 경험과 작은 잔여 batch를 처리합니다. 각 모델 체크포인트에 해당 행의 완료 횟수를 먼저 저장한 뒤 DB에 반영하고, **두 모델 모두 학습과 저장을 끝낸 행만 삭제**합니다. 승급 성공 여부는 학습 경험 삭제 조건이 아닙니다. 입력이 맞지 않는 행은 삭제 대신 보류하며 학습 가능한 미학습 수와 따로 표시합니다.
- 실주문은 기본 OFF입니다. 사용자가 명시적으로 켜기 전까지 실제 주문을 내지 않습니다.
- 시장 추론과 두 모델의 학습 작업은 분리합니다. 학습 중 변경하는 Champion 작업본을 실시간 판단에 직접 사용하지 않습니다. 같은 GPU를 공유하므로 계산 경쟁에 따른 지연은 실제 측정값으로 확인합니다.
- 화면에는 새 경험 수와 별도로 남은 학습 가능한 replay, 진행 중 optimizer 단계·처리 경험 수, 고정 시험본의 검증 진행을 표시합니다. 검증 중이라는 이유로 Candidate 학습이 중단된 것으로 표시하지 않습니다.
- API의 `candidate_learning_enabled`는 학습 루프 활성 상태이며 `candidate_start_ready`는 학습 가능한 경험이 남아 있는 상태입니다. 장 종료나 실시간 시세 대기 때문에 남은 학습을 멈추지 않습니다.
- 정지·재시작 요청 시 학습 중인 모델은 진행 중 optimizer 단계까지만 완료한 뒤 실제 갱신된 가중치와 해당 모델의 replay 사용 횟수를 저장합니다. 정지 요청 후 다음 단계를 추가로 시작하지 않습니다.

## 하루 전체 경험의 순차 학습

현재 우선순위는 수집된 유효 경험을 빠뜨리지 않고 학습하는 것입니다. **입력 길이 128칸은 하루에 배우는 경험 수 제한이 아닙니다.** `1~128 → 2~129 → 3~130`처럼 입력 창을 옮기며 수집된 하루 전체를 처리합니다. 128봉 승급시험도 별도의 평가 길이이며 학습량 제한이 아닙니다.

- 같은 시장·계좌 입력을 공유하는 종목 경험은 Transformer 입력 계산을 공유하고 각 경험의 손실을 모두 합산합니다. 종목이나 경험을 일부 버려 계산량을 줄이지 않습니다.
- 겹치는 입력 창은 같은 SQLite의 압축된 프레임을 공유합니다. replay DB를 하나 더 만들거나 경험용 `.pt` 파일을 만들지 않습니다.
- 아직 결과가 나오지 않은 판단도 당시 입력과 함께 같은 DB에 저장합니다. 재시작·주말·장 마감으로 만료시키지 않습니다. 재시작 후 남은 경험과 사용 횟수를 복구합니다.
- 장중 학습이 수집을 따라가지 못하면 남은 경험을 보존하고 장 마감·주말에도 학습합니다. 시스템과 컴퓨터가 켜져 있어야 진행됩니다. 주말에 전부 끝날지는 실제 수집량과 학습 속도로 판단합니다.
- 용량이 커졌다는 이유로 학습 전 경험을 삭제하거나 4,096건에서 잘라내지 않습니다. 50 MiB는 저장량 알림 기준이며 삭제·쓰기 제한이 아닙니다. 미학습 분량이 쌓이는 동안 용량은 늘어날 수 있습니다.
- 운영실에 한국시간 기준 날짜별 생성량·두 모델의 1회 이상 학습량·두 모델 각각 2회 학습 및 저장 완료량·남은 학습 가능 분량을 표시합니다. 학습 불가·보류는 따로 표시합니다. 두 모델 학습 도입 전에 완료된 과거 집계는 당시 단일 모델 기준을 유지하며, 이미 삭제된 경험을 두 모델이 다시 배웠다고 주장하지 않습니다.

현재 수집 범위는 공급자가 실제 제공한 봉·시세입니다. ITCH의 모든 개별 호가·체결 메시지를 수집·학습한다고 주장하지 않습니다. 공급자 누락과 아직 완료되지 않은 보상은 완료된 학습량과 구분합니다.

## 모델

글로벌 Transformer는 시간축과 여러 종목·시장 문맥을 함께 처리합니다. 설계 목표는 약 0.5B 파라미터 규모이며, 체크포인트에 따라 실제 구조와 크기가 다를 수 있습니다. 시간축 128칸은 종목 수 제한을 뜻하지 않습니다. GRU와 teacher 기반 학습은 초기 비교·부트스트랩 연구입니다.

종목별 시세 시각이 다르므로 각 종목의 입력 창 안에서 마지막 유효 관측의 출력 상태를 사용합니다. 최신 공통 시각에 새 시세가 없는 종목의 과거 관측을 0으로 버리지 않습니다. 추론과 활성화 재계산을 사용하는 두 모델의 학습은 같은 출력 규칙을 적용합니다.

실시간 판단의 본체 입력은 **최근 수집 시점 128칸**입니다. 공급자가 분봉과 초 단위 체결을 함께 보내면 128칸이 정확히 128분을 뜻하지 않습니다. 여기에 `1m·3m·5m·15m·60m·1d·1w·1mo`의 완료된 봉에서 만든 종목별 보조 입력을 한 번에 붙입니다. 각 시간봉에는 최근 변화, 해당 시간축의 긴 구간 변화, 가격 범위, 거래량 변화, 최신성, 확보된 기록 비율을 구분해 넣습니다. 긴 구간은 일봉 64개·주봉 52개·월봉 24개이며, 기록이 부족하면 해당 값과 확보 비율로 부족함을 드러냅니다. 큰 Transformer를 시간봉마다 반복 실행하지 않고 작은 학습 가능한 보조층이 정보를 합칩니다.
기존 `time_scale_embedding`의 크기는 바꾸지 않습니다. 세부 시간봉은 보조 입력의 고정된 순서로 구분하므로 종전 체크포인트를 읽을 수 있습니다.

기존 Champion/Candidate 가중치 형식은 유지합니다. 새 보조층은 처음에는 출력이 0이어서 기존 판단을 바꾸지 않고, 이후 실제 paper 경험으로 두 모델이 각각 학습합니다. Candidate의 Champion 교체는 동일한 미래 구간 승급 검증을 통과해야 합니다. `configs/live_symbols_korea.json`의 `decision_timeframes` 순서는 모델 입력 순서와 일치해야 합니다.
`/api/status`의 `metrics.multiscale_coverage`는 시간봉별 실제 입력 기록 확보 비율을 보여줍니다. 장기 일봉 기록이 아직 수집되지 않았다면 주봉·월봉 수치는 0에 가깝습니다.
운영 화면의 **모델 판단 입력**은 `1·3·5·15·60분봉 + 일·주·월봉 통합 판단`으로 표시합니다. 단일 시간 선택창은 제거했습니다. 매번 확보된 여러 시간봉의 완료 데이터를 함께 사용하며, 시간봉별 실제 확보 상태는 위 지표로 확인합니다. 이 화면 변경은 내부 보상 평가 기간이나 학습·승급 설정을 변경하지 않습니다.

## 운영 확인과 백테스트

운영실의 **새 모델 적용 기준**에 현재 optimizer 진행 횟수·처리한 replay 수·아직 배우지 않은 경험 수·검증 진행·대기열·시세 지연과 오류를 표시합니다. 마지막 완료 학습량과 VRAM 측정은 별도로 유지합니다. 시간봉별 확보 비율과 매수/매도 호가를 실제로 제공하는 종목 수도 상단에서 확인합니다. 입력 목록에 있다고 모든 종목에 충분한 기록이 확보됐다는 뜻은 아닙니다.

백테스트는 운영·승급 검증과 같은 `PaperAccount`를 사용합니다. 현금, 보유량, 추가매수·부분매도, 판단 다음 관측에서의 체결, 수수료·매도세 가정·스프레드·슬리피지를 반영한 순자산 성과를 계산합니다. KRW와 USD의 실제 금액을 합산하지 않고 각 시드머니로 정규화한 수익률을 비교합니다. 같은 데이터에서 추론을 두 번 수행하지 않습니다. 과거 진단 백테스트는 학습 이력이 따로 확인되지 않는 한 미학습 구간 성과라고 주장하지 않습니다. 승급은 별도의 미래 시험으로만 결정합니다.

현재 직접 가상매매 가능한 자산은 주식·ETF이며 나머지는 시장 문맥입니다. 키움 체결의 최우선 매수·매도 호가는 입력할 수 있지만 전체 호가 잔량을 지원한다고 주장하지 않습니다. 실제 매매 수익 개선은 학습 횟수나 가중치 변경만으로 확정할 수 없으며, 동일 미래 계좌 비교 결과로 확인합니다.

검증 대기열은 전체 시장 이력을 복제하지 않고 최근 입력 창만 담는 RAM 관측본 32개로 제한합니다. 두 모델 학습의 optimizer batch와 시험본·관찰본의 GPU 이동은 같은 자원 잠금으로 조율합니다. Champion 추론은 독립적으로 계속합니다. JSON 상태 저장은 파일별 쓰기를 직렬화하고 짧은 Windows 공유 충돌을 재시도합니다.

관련 회귀 확인은 프로젝트 루트에서 `python -m unittest discover -s tests -v`로 실행합니다.

## 실행

Windows에서 프로젝트 루트의 `StockRL Start.bat`을 실행합니다. 로컬 운영 화면은 `http://127.0.0.1:8766/`, 상태 API는 `http://127.0.0.1:8766/api/status`입니다. 실행 중 상태는 API에서 확인하며, 과거 저장 지표만으로 현재 작동 여부를 판단하지 않습니다.

Python 3.10 이상과 실행 환경에 맞는 PyTorch가 필요합니다.

```powershell
python -m pip install -e .
```

## 파일과 저장 공간

- **소스·설정·문서:** 이 Git 프로젝트에 둡니다.
- **모델 가중치:** `champion.pt`, `candidate.pt`는 Hugging Face에 보관합니다. 모델 가중치만 GitHub 업로드 대상에서 제외합니다.
- **운영 데이터:** 프로젝트 안의 `runtime/markets/<market>/live`에 둡니다. runtime을 포함한 프로젝트 파일을 GitHub에 함께 저장해 다른 컴퓨터에서 프로젝트를 내려받으면 paper 계좌·replay·cursor·시세 데이터까지 이어받도록 합니다.
- **여러 시간봉 기록:** 1분봉은 기존 `market.csv`를 사용하고, 완료된 일봉은 같은 runtime의 `timeframes.sqlite3` 한 파일에 종목당 최근 600개까지만 보관합니다. DB 본문에는 32 MiB 상한을 둡니다. 3·5·15·60분봉은 최근 1분봉으로, 주봉·월봉은 이 일봉 기록으로 만듭니다. 아직 완성되지 않은 상위 봉과 판단 시점 이후 데이터는 입력하지 않습니다.
- **저장 공간:** 판단·오류·실행 기록은 정해진 크기에 닿으면 같은 파일을 비우고 새 기록을 씁니다. 시세 cache는 저장 cursor 이후의 미처리 봉과 필요한 입력 문맥을 보존합니다. replay는 두 모델 모두 학습과 저장이 끝난 행만 삭제하고 빈 공간을 회수합니다. 미학습 데이터 보존을 저장 용량 한도보다 우선하므로 밀린 분량이 많으면 runtime이 과거 100 MiB 목표를 넘을 수 있습니다. 필요하면 사용자가 허용한 모델 폴더로 학습 DB만 옮길 수 있습니다. 날짜별 snapshot/archive 복사본은 만들지 않습니다.
- **판단 집계:** `decisions.csv`는 열 제목줄을 포함해 저장합니다. 대시보드의 BUY/HOLD/SELL 건수는 이 파일의 최신 종목별 판단을 집계합니다.
- **대시보드:** `src/stockrl/web_dashboard.html`이 기준 파일입니다. 하드디스크에 별도 HTML 백업 파일이나 백업 폴더를 만들지 않습니다. 수정 전 현재 프로젝트를 GitHub에 commit·push하고 원격 저장을 확인한 뒤 수정합니다.
- **가상계좌 초기화:** 운영 제어의 서버 재시작 버튼 옆 `계좌 초기화`는 Champion 운영 계좌와 Candidate 관찰 계좌의 시드머니·보유 종목·체결·누적 손익을 초기화하고, Champion의 최근 판단 방향 기록도 비웁니다. 모델 가중치와 replay는 유지합니다. 실행 중이면 학습·시세 상태를 저장한 뒤 시스템을 다시 시작하며, 새 판단이 들어오면 방향 기록이 다시 쌓입니다. 진행 중인 승급 검증은 재시작 시 무효 처리됩니다.
- **Git 제외:** `.pt`, `.pth`, `.ckpt`, `.safetensors` 모델 가중치만 제외합니다. 그 밖의 프로젝트 파일과 runtime 파일은 제외하지 않습니다. GitHub 파일 하나가 100MB를 넘지 않도록 유지합니다.

## 데이터·연구 도구

ITCH, FI-2010, FinRL, TradeMaster, MacroHFT 등 공개 시장 데이터와 연구 코드는 선행학습·비교 실험의 재료입니다. `scripts/`와 연구용 모듈의 결과가 운영 Champion에 자동 적용되지는 않습니다. 모든 학습과 비교는 시간순 데이터를 사용하고 미래 정보 누수를 피해야 합니다.

## 현재 상태 확인

`GET /api/status`에서 feed와 agent 진행 상태, 두 모델 각각의 학습·optimizer 갱신·계산 시간·peak VRAM·남은 경험, replay 건수, 검증 bar, 승급·거절, Champion과 Candidate 계좌 및 실제 주문 OFF 상태를 확인합니다. 프로세스가 살아 있다는 표시만으로 판단이나 학습이 진행 중이라고 보지 않습니다.
