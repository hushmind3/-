# StockRL 시장 관찰실

현재 저장 기준: runtime은 프로젝트 폴더의 `runtime/markets/korea/live`에 둔다. 다른 시장은 `runtime/markets/<market>/live`에 분리한다. replay는 bounded SQLite, 계좌와 검증 상태는 JSON으로 저장하며 미성숙 경험 목록은 실행 중 메모리에 있다. 검증 자료는 최근 64개 검증 시각을 사용한다. 모델 폴더에는 `champion.pt`와 `candidate.pt`만 둔다. 아래의 화면 설명에는 이전 구현 기록도 있으므로, 현재 동작은 코드와 이 저장 기준을 따른다.

## Windows 한 번 실행

바탕화면의 **StockRL 시장 관찰실** 바로가기를 더블클릭합니다. 인터넷 연결이 필요 패키지를 설치하고, 웹 서버와 paper 관찰기를 시작한 뒤 브라우저를 엽니다. 운영 포트는 `8766`입니다. 실제 증권 주문은 연결되어 있지 않습니다.

프로젝트 폴더에서 직접 시작하려면 `StockRL Start.bat`을 더블클릭합니다. 종료하려면 화면의 `전체 정지`를 누르거나 실행 콘솔에서 `Ctrl+C`를 누릅니다.

## 화면에서 하는 일

- **시장 현황 · 운용 제어:** 한국, 미국/NASDAQ, 일본, 홍콩, 독일, 영국 지수, 선물, 국채 금리, 환율, 가상자산을 분리해 봅니다. 거래소별 현지 시각과 장중/장외는 달력 휴장을 반영하지 않는 시간대 안내입니다.
- **시장 판단 필터:** 판단 표의 표시 대상만 거릅니다. 선택을 바꿔도 모델 입력 시장은 설정된 전체 universe입니다.
- **Shadow Trading / 관찰 전용:** HOLD 판단과 별개인 스위치입니다. 관찰 전용에서도 추론, 결과 채점, replay 학습은 계속됩니다. 현 구현에는 현금·수량·평단을 계산하는 체결 장부가 없습니다.
- **평가 구간:** 30초/1분/5분 뒤 판단 보상을 평가합니다. 실행 중에는 현재 세션 설정이 유지되므로 바꾸려면 전체 정지 후 다시 시작합니다.
- **한국 시세 연결 설정:** 한국투자증권 또는 키움증권 App Key를 OS 자격 증명 저장소에 넣고 OAuth 인증을 시험합니다. 자격 증명 저장/인증 확인은 실제 주문 연결이나 현재 시세 피드 전환을 뜻하지 않습니다.

## 데이터 범위

현재 설정은 KRX/KOSDAQ 주식 80개와 미국 주식·지수, 글로벌 대표 지수, 미국 지수 선물, 원자재 선물, 국채 금리, 환율, VIX, 가상자산 등 참고 심볼 30개(총 110개)입니다. 무료 공개 feed는 Yahoo/Kraken 어댑터를 사용합니다. 호가 원장/체결 원천 데이터가 아니며, 모든 거래소·모든 종목을 포함하지 않습니다.

## 가상매매 버튼의 현재 동작

`가상매매`를 켜면 현재 champion의 BUY/HOLD/SELL 판단 중 **새로 관측된 한국·미국 주식과 ETF**를 대상으로 가상 주문을 만듭니다. 판단이 나온 봉에 체결하지 않고 해당 종목의 **다음 확정 봉 종가**에 체결합니다. 한국 원화 1,000만 원과 미국 달러 1만 달러는 서로 독립된 초기 가상 자금입니다. 현금 초과매수와 보유수량 초과매도를 막고, 수수료·슬리피지·가능한 스프레드 및 한국 주식 매도세 가정치 0.1%를 비용으로 기록합니다. 세율은 실제 세금 안내가 아닌 시뮬레이션 가정치입니다.

가상 현금, 수량, 평단, 체결 내역, 평가 순손익은 프로젝트 안 `runtime/markets/korea/live/agent/paper_account.json`에 저장되며 재시작 때 복구됩니다. 모델 폴더에는 `champion.pt`와 `candidate.pt`만 둡니다. replay는 같은 runtime의 SQLite에 저장하며 `.pt` 파일로 만들지 않습니다. `관찰만`으로 바꾸면 새 가상 주문을 취소하고 기존 보유량은 그대로 두며 시세 평가는 계속합니다. 실제 주문은 연결하지 않았습니다.

매수 예산은 현재 모델의 BUY 확률에 따라 가용 현금을 나누는 실행 규칙입니다. **일반 champion에는 자금배분 head가 없을 수 있습니다.** 온라인 학습에는 가상계좌 순손익이 보상으로 들어갑니다. 다만 현재 checkpoint가 계좌 상태 입력과 자금배분 출력을 지원하는지에 따라 승격 비교 방식이 달라집니다. 이를 지원하는 모델은 같은 검증 구간의 계좌 결과로 비교하고, 일반 모델은 같은 구간의 BUY/HOLD/SELL 순손익으로 비교합니다. 화면은 계좌 손익과 판단별 보상을 나눠 보여줍니다.

## macOS

프로젝트를 복사하고 Python 및 PyTorch를 설치한 뒤 `scripts/run_korea_paper_web.command`를 실행합니다. `--device auto`는 CUDA, MPS, CPU 순으로 가능한 장치를 선택합니다. MPS 동작은 실제 Mac에서 별도 확인해야 합니다.
